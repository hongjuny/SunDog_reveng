# SunDog Apple II → macOS 네이티브 포팅

원본을 디스어셈블하고 게임 로직·자료구조·입출력·렌더링의 의미를 복원한 뒤,
그 내용을 Swift 등 macOS 네이티브 코드로 구현한다. Apple II/6502 에뮬레이터나
p-code 실행기를 제품 코어로 넣는 방향은 중단했다. 원본 실행 자료는 분석 결과를
대조하는 근거로만 사용한다.

## 현재 실행 중인 단계

최신 0.5 빌드는 원본 디스크에서 추출한 첫 타이틀을 표시하고, 원본 native
루틴의 중앙→바깥 확장을 Swift로 재현한다. [부트 경로](boot-to-splash.md)와
[8,041회 화면 쓰기 검증](splash-reveal.md)을 마쳤다. 물리 주사 동기화와 실제
창 표시는 별도 미검증이며, 게임 로직 전체가 연결된 것은 아니다. 아래 0.2/0.3
기록은 그 이전 단계의 성과다.

2026-10-23: 구조적 디스어셈블은 [독립 감사](disassembly-coverage.md)를 통과했다.
원본 글리프·입력 필터를 Swift로 이식하고, 검증한 원본 font prefix를 사용한
[네이티브 앱 0.2](native-app.md)를 빌드했다. 이는 렌더링/입력 포팅 단계이며
게임 장면·규칙·저장 기능은 아직 연결되지 않았다. 아래 초기 분석 수치보다
최신 디스어셈블 수치는 감사 문서를 기준으로 한다.

후속 0.3에서는 P48/P47/P45의 실제 문자열 배치를 앱에 연결하고, segment21의
8개 참조 인자 대응과 맵 선택식을 확인했다. [문자 배치](text-layout.md)는
원본 decoded CFG 50사례, [맵 선택](event-contract.md)은 원본 native handler를 통한
293사례와 대조했다. P44 하단 처리, 장면 맵 생성·수명, 실제 입력에서 선택 결과로
이어지는 전체 장면 루프는 남아 있다.

[게임 코드 분석](game-code-analysis.md)에 현재 증거와 한계를 기록한다.
Play의 SYSTEM.STARTUP 13개 segment/327개 procedure를 구조 검증했고, 라이브러리와
런타임을 포함한 정적 p-code 호출 관계를 생성했다. 문자열 배치에서 native HGR
글리프 쓰기로 이어지는 경로를 찾고 정상 합성 body의 420개 경우를 대조했다.
게임 시작의 상태 dispatcher와 native 입력 래치 hook을 추가로 확인했다. 산술 helper
하나를 명세·733개 사례로 대조한 뒤 `native/`의 Swift 함수로 옮겼다. 게임 전체의
상태 모델과 규칙은 아직 복원되지 않았다.

| 순서 | 해야 할 일 | 통과 기준 |
|---|---|---|
| 1. 원본 코드 지도 | Pascal/native 구분, procedure/call/branch, 실제 disk payload 대응 | 출처가 있는 호출 지도와 미확인 경계 목록 |
| 2. 시작·입력 흐름 | 초기화, game loop, 입력 sampling과 명령 dispatch | 입력 하나가 상태 변경/화면 갱신까지 이어지는 절차 설명 |
| 3. 화면 시스템 | 글꼴·문자열·window·cursor·sprite·clipping·dirty update 복원 | 원본 알고리즘의 인자/상태/메모리 효과 명세 및 경계 검증 |
| 4. 게임 규칙 | 거래·화물·우주선·항법·도시·행성·지속 상태 복원 | 소유 자료구조와 규칙/계산/부작용을 함수 단위로 설명 |
| 5. 네이티브 구현 | 검증한 함수와 상태 모델을 네이티브 코드로 재작성 | 원본 함수의 입력/출력 사례 및 화면 결과와 일치 |
| 6. 앱 연결 | 창·입력·음향·파일·저장 UX와 네이티브 게임 모델 연결 | 실제 한 게임 활동, 저장, 종료, 재실행 복원 완료 |
| 7. 전체 검증 | 주요 플레이 경로, 장기 상태, 시간·성능·배포 확인 | 회귀 시나리오와 충실도 기준 통과 |

각 기능은 분석 근거와 계약을 먼저 확보한 뒤 구현한다. 일부 렌더링 식의 검증이나
앱 셸 빌드를 게임 로직 포팅으로 계산하지 않는다. 과거 `Sources/`의 캡처 뷰어는
검증용 실험이며 제품 구현의 근거로 간주하지 않는다.

우선 작업은 segment 21의 참조 인자/event 구조, 거래 caller의 잔액·재고 변경,
segment 22의 문자열/문자 렌더링 계약과 미확인 서비스다. Play T34는 계속 unknown이며 유효한 0-valued
sector로 취급하지 않는다. 원본 미디어와 추출 바이너리는 공개 저장소에 넣지 않는다.
